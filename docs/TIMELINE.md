## 착수 · 설계 (2026-08-15)

- kitchen-fire-poc(유니폼 지름길로 49.7% 실패)와 **독립** 프로젝트로 새 저장소 생성.
  같은 원본 영상은 쓰되 가중치·튜닝값은 재사용하지 않음.
- 목적 두 가지: ① 합성 화재를 학습해 화재를 인식하는가 ② 노이즈에 강건한가(+극복).
- 확정 설계는 `docs/PREREGISTER.md` 에 사전 등록(프레임 보기 전).

## 데이터 분할 — 사이트 단위 (사전 등록)

- 급식실 조리영상 **28개 · 13사이트**(전부 불 없는 배경). `scripts/videos.json`.
- 사이트 단위로 train 9 / val 2 / test 2 배정. **test = 개원중(유일 CCTV) · 내곡중**,
  val = 로봇고 · 인화여중. 같은 주방이 두 세트에 안 겹치게(누수 방지).
- 조리종류 균형은 강제하지 않고 per-dish 로 보고하기로(공백을 숨기지 않음).

## 배경 프레임 추출

- 1fps + 중복제거 + 사이트당 400 상한.
- **[경로 수정]** 중복제거 기준 0.90 이 고정 CCTV(개원중)에 너무 공격적 —
  280장 중 **1장**만 남아 test 핵심 사이트가 붕괴. 기준을 **0.99** 로 완화 →
  개원중 **210장**으로 회복. 배경은 불꽃 캔버스라 유사해도 무방하다는 판단.
- 최종 **2,881장** (train 2,278 / val 294 / test 309).

## 불꽃 소재 — 실제 유류화재에서 매트 추출

- 렌더 불꽃은 안 씀(그게 kitchen-fire-poc 실패 원인). smoke_frames 의 **실제
  유류화재 영상**에서 불꽃 구간만 오려냄. 색·휘도 기반 알파 매트.
- 후보 11개 → **7개 통과 · 3개 탈락 · 1개 제외**:
  - 탈락 `grease_safety`(밝은 회색 배경이 통째로 샘), `ih_debris`·`dented_pan`
    (빨간 LED 시계·온도표시가 난색이라 샘). `kyofu` 제외(자막·사람 앵글).
  - **[경로 수정]** 초기 매트가 밝은 배경·자막에 샘 → 난색 하한(w0) 추가·core0 상향,
    연결요소 정리(speckle·자막 제거), 자막 있는 출처는 crop. 재추출 후 7개 통과.
- 스프라이트 **257장**. 풀: **train 5**(tempura01·konro_ignite·low_oil·reproduce·
  dirty_pan, ~140장) · **test 2**(clean_pan·grease_prev, ~56장). 출처 단위 분리(누수).

## 합성 — 배경 위 불꽃 + 자동 박스

- 풀 매칭: train 합성=train 배경+train 불꽃, test 합성=test 배경+test 불꽃(누수 차단).
- 제약된 무작위 배치(하단~중앙), glow 블렌딩(경계선 지름길 완화), 하드네거티브
  (회색 블롭 — "붙인 것 ≠ 불" 학습), 자동 박스(알파 마스크 = 정답).
- YOLO 데이터셋: train 2,278(양성 1,365·하드네거 341·음성 572) /
  val 294(192·33·69) / test 309(193·48·68).

## 학습 (5단계)

- YOLOv8s, COCO 사전학습에서 시작. val 로 best.pt 선택(연기 프로젝트와 달리 val≠train).
- **test mAP@0.5 0.763 · 이미지단위 검출 86%** (미학습 급식실+미학습 불꽃).
  val mAP@0.5 0.975. val→test 격차는 "미학습 불꽃"이 주원인 = 누수 없는 건강한 격차.

## 검증 — 모델이 진짜 불꽃을 보는가 (핵심)

- **[방법 실패]** EigenCAM 은 클래스 비특정(모든 강한 구조에 반응)이라 판정 불가.
  히트맵이 급식실 전체에 퍼짐 — 지름길 여부를 못 가림.
- **[결정적] 불꽃 제거(ablation) 검증**: flame_rate **0.86** · 같은 배경(불꽃 제거)
  검출 **0.000** · test 음성 116장 오탐 **0/116**. → **모델은 실제 불꽃을 필요로 하며
  배경·유니폼·경계선 지름길을 쓰지 않는다.** kitchen-fire-poc 실패와 정반대. **통과.**
- **→ Experiment 1(합성 학습이 진짜 불꽃을 배우는가) 사실상 완료.**

## Phase A 노이즈 저하 곡선 — 미리보기 (1 seed, 강도 보정용)

- 노이즈 9개(gaussian·jpeg·motion_blur·defocus·low_light·steam·contrast·grayscale·
  random_erasing) 강도 0~5.
- 발견: **gaussian** 급락(가장 취약), **random_erasing**·low_light·contrast·grayscale
  저하. **jpeg·grayscale 은 고강도서 오탐(헛경보) 유발**(0.47·0.59) — 놓침과 다른
  실패 모드. **steam 에 안 속음**(오탐 0, 유지 0.79) — 연기 프로젝트의 김↔불 혼동을
  이 검출기는 안 겪음. blur류는 견고.
- 강도 보정 판정: **양호, 그대로 본 실험 진행**.

## 오염 발견·수정 — konro_ignite 빨간 LED (2026-08-18, Phase B 착수 중)

> Phase B 학습을 이미 돌리기 시작한 뒤에 발견함. 잘된 것만 적으면 이런 일이 안
> 보인다 — 그대로 남긴다.

- **발견**: Phase B 증강셋(`train_aug_modelA`) 이미지를 육안 점검하다, 일부 합성
  이미지에 불꽃과 함께 **빨간 LED 시계 "00:27:05"** 가 찍혀 있는 것을 봄.
- **원인**: `konro_ignite`(火災再現実験動画 こんろ火災編)는 **탈락시킨 ih_debris 와
  같은 札幌市消防科学研究所 시리즈** → 화면에 빨간 LED 타이머가 있음. 빨강이 난색이라
  매트가 불꽃으로 오인해 스프라이트 **31개 전부**에 오려 넣었음.
- **왜 ablation 이 못 걸렀나**: LED 가 불꽃 스프라이트 *안*에 있어, "불꽃 제거 →
  검출 사라짐" 검증으로는 LED 가 같이 지워져 지름길로 안 잡혔음. (검증의 사각지대)
- **범위 확정**: 7개 소재 폴더를 전수 육안 확인 → **konro_ignite 하나만** 오염.
  나머지 6개(train 4 + test 2)는 깨끗.
- **1차 시도(실패)**: 색 기반 제거(green-floor, R 높고 G·B 낮은 픽셀 삭제).
  LED 빨강은 지웠으나(잔여빨강 0.000) **konro 불꽃도 파괴**됨 — konro 불꽃 자체가
  깊은 빨강이라 LED 와 **색으로 구별 불가**. green-floor 되돌림.
- **결정 (A) konro_ignite 탈락**: ih_debris·dented_pan 과 동일하게 제외.
  train 풀 5→4(tempura01·reproduce·low_oil·dirty_pan), test 2 유지.
- **영향**: 학습 이미지 수는 배경이 정하므로 불변(2278/294/309), 불꽃 종류만 감소하나
  크기·모양 다양성은 유지. **오염 데이터 기반 산출물(Phase B 모델·synth·ablation·
  Phase A 미리보기)은 전부 폐기 후 깨끗한 데이터로 재생성.**
- **교훈**: 같은 실험 시리즈의 소재는 *한 프레임 QC* 로는 부족하다 — 프레임마다 다른
  오염(타이머·자막)이 들어갈 수 있어 전수/증강 산출물까지 봐야 한다.

## 실제 화재 검증셋 준비 · simulation 배제 (2026-08-18, Phase B 학습 중 병행)

> v8 학습(진행 중)과 무관하게 하류 준비를 함. 실행은 학습 완주 뒤.

- **[경로 수정] ablation·realfire 의 BEST 가 옛 오염 모델을 가리킴**: 둘 다
  `runs/fire_s/best.pt`(konro 오염 시절의 구 단일학습)를 가리키고 있었음. 파일이
  남아 있으면 오염 가중치로 조용히 돌고, 지웠으면 종료 — 어느 쪽이든 틀림.
  → 깨끗한 **`runs_phaseB/v8_baseline_s1/best.pt`** 로 교체(`BEST_MODEL` 변수로 분리).
  HANDOFF 가 ablation 만 예고했으나 realfire 도 같은 버그였음.
- **구간 주석 도구 추가** `colab_realfire_annotate.py`: 각 영상을 2초 간격 썸네일
  격자로 펼치고 각 칸에 정확한 초(mm:ss)를 박음. 스크럽 없이 발화 시점을 잡기 위함
  (CPU, GPU/학습과 무관). 이 시트로 대략 잡고 → 웹 플레이어로 경계 다듬는 절차.
- **채움**: 후보 6개 중 **5개 사용** — jikken_douga·tokyo_bousai·kanetsu·
  grease_spread·hisomu. 예상 불꽃 **~406장**(목표 ~100의 4배), 발화전 ~244장.
  구간은 시트 근사값이라 필요시 웹 플레이어로 재조정 가능.
  - `hisomu` 는 fire 만: 발화 전 구간에 파란 가스버너 불꽃이 계속 보여 깨끗한
    nofire 를 못 잡음 → nofire 생략(다른 4개로 충분).
- **[결정] simulation 배제**: `天ぷら油火災シミュレーション` 은 애니 삽화와 실사가
  섞여 **실사 불꽃 프레임을 깨끗이 분리 불가**. 경계를 잘못 잡으면 만화 불이
  fire_shots 에 섞여 `real_flame_rate` 를 **거짓으로 낮춤**(놓친 게 아니라 애초에
  검출 대상이 아닌 것을 섞는 비대칭 손해). 아무리 촘촘한 시트도 경계 오차가 0 은
  아니므로, **이미 5개·목표 4배**인 상황에선 얻는 것(미미)보다 오염 위험이 큼.
  → **사전 원칙 배제.** 성능이 안 나와서가 아니라 *자료 품질* 이유라는 점에서
  konro_ignite 오염 배제와 **동일 성격**. (`fire_shots` 빔 → realfire_test 자동 건너뜀.)
- **[결정] 실행 계정 통일 = seochorobotics**(Colab Pro+ · L4): best.pt(fire_frames)가
  거기 있음. 영상(smoke_frames, blessmoonkh 소유)을 seochorobotics 에 공유+바로가기
  추가해야 `colab_realfire_test.py` 가 한 계정에서 모델·영상을 다 봄.
- **교훈**: 검증셋도 학습셋과 같은 원칙 — 깨끗한 5개 > 오염 위험 있는 6개.
  품질이 수량을 이긴다. 배제는 사전에, 이유를 적어 남긴다.
