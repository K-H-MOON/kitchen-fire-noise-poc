# 미팅 이후 과정 요약 (2026-08-24~, 진행 중)

> [미팅용 요약(SUMMARY_meeting.md)](SUMMARY_meeting.md)이 v1~v3까지라면, 이 문서는 **회의 후 새 방향의 진행 기록**이다. 결론: v1~v3로 **병목 = 데이터/도메인(합성↔실제 간극)**으로 좁혀졌고, 회의 후 **실제 화재 데이터**로 공략 → **실험 A: 실데이터 학습이 놓침을 없앰**(Indoor recall 0.235→0.985, §5). **누수 통제 재측정 0.899로 견고**(누수 ~8.6점). **도메인 이동 파일럿(§6): 유류화재 test에서 큰불(§C) 실 0.985·초기작은불(§D) 실 0.97~1.0 vs 합성 0.52·0.27** — 실데이터가 유류화재 큰불·초기불 모두에 전이. **헛불 검증(§E): 실데이터 모델이 주황조명·어두운스팀에 헛불(fpr ~0.22, 누수통제 그룹 0.085로 최선).** **헛불 고치기(§F): 하드네거 재학습은 사실상 무효 — 주황조명(13476222)이 모든 실모델에서 fpr 0.875~1.0 요지부동. 진단(예측박스): 헛불 정체 = 배경의 작은 "따뜻한 장식 전구"(점광원)를 소형 화염으로 착각. 학습에 본 주황장면은 억제(0/5)·안 본 장면은 실패(7/8) → "장면 다양성 부족"(고칠 수 있음). **✅ 결정: 급식실 전용이라 주황 조명 out-of-domain → 저순위(수집 안 함). 부수 함의: 배포 도메인(밝은 주방·스팀)에선 헛불이 raw 수치보다 작음(최대 기여자가 out-of-domain). 진짜 레버 = 배포-대표 데이터 → A안 전이학습.** 단 장면 N=4·급식실 시점 미검증(방향성 신호). **★A안 데이터 수집 완료(§7, 2026-08-25): 실 주방/유류 화재 영상 69개→검수→28장면(실 in-situ 주방 CCTV·NIST lab 포함) 확보, fine-tune 문턱 충족 — "데이터 다양성" 피드백에 실행으로 대응. 다음=현재 모델 실화재 재측정→필요 시 fine-tune.**

## 회의에서 정해진 방향
- v1(불꽃 현실성)·v2·v3(표현/DINOv3) 모두 실제 전이 못 올림 → **병목은 모델이 아니라 데이터/도메인.**
- → **실제 화재 데이터**를 확보해 학습/평가에 투입(합성만으로는 진짜 불을 못 배움).

## 단계별 진행

**1. "무엇을 놓치나" 진단 (error-analysis) — 그리고 평가셋 오염 발견**
기존 모델을 실제 화재에 돌려 놓침 패턴을 분석하려 했다. → 그 과정에서 **평가셋 자체가 오염돼 있음을 발견.**

- **realfire 5편 중 최소 3편(jikken·kanetsu·hisomu)이 편집된 소방 홍보(PSA) 영상**이다 — PIP·자막·만화 불·타이틀 카드. "fire" 라벨이 붙은 프레임에 **실제 불이 없거나 그래픽에 가려짐** → 모델이 정당하게 안 잡은 것을 "놓침"으로 오집계.
- **"밝은 장면을 못 잡는다"는 완전한 착오였다.** 그 "밝음"의 정체는 불이 아니라 **파란 타이틀 카드·분홍 만화 배경·흰 자막의 밝기**였다. → **육안으로 안 봤다면 "밝은 장면 화재"라는 엉뚱한 방향으로 데이터를 모을 뻔했다** (error-analysis를 먼저 한 것이 이걸 잡아냄).

![realfire 오염 예시 — kanetsu 편](img/realfire_contamination_kanetsu.jpg)

> **그림.** kanetsu 편(소방 PSA)의 "놓침"으로 집계된 프레임 예시. **왼쪽**: "fire" 라벨이지만 실제 불은 없는 **파란 타이틀 카드**(밝기만 높음) — "밝은 장면 못 잡음"의 정체. **오른쪽**: 실제 큰 튀김유 화염이지만 "天ぷら火災の消火方法"·"吹田市消防本部" **자막·브랜딩이 덮인 편집 화면** — 둘 다 모델 무검출(conf 0.00)로, 오염된 평가에서 놓침으로 오집계됨. (출처: 吹田市消防本部 화재 예방 PSA 캡처 · error-analysis 육안 판독용 저해상 인용.)
- 추가로 발견한 것: **grease 편은 nofire 오라벨**(실제 불 포함) + 야외 화재 → 정확 검출이 FP로 오집계.
- **정리: 기존 realfire recall(0.31·0.27 등)은 심하게 오염·과소평가된 값이다. 모델이 실제 화재에서 얼마나 하는지 우리는 아직 제대로 모른다.** (상대 비교는 같은 셋 공유라 비교적 견고, 절대값만 신뢰 불가.)

→ **바로 이것이 이후 모든 작업의 출발점이다:** 오염된 기준으로는 성능을 알 수 없으므로, **깨끗한 실제 데이터를 확보해(2) 오염 없는 기준으로 다시 재고(3), 놓침의 진짜 원인을 진단하고(4), 실데이터 투입으로 고쳐본다(5, 실험 A).**

**2. 실제 데이터 확보·검증**
- **Indoor Fire Smoke** (5000장·YOLO·fire/smoke, 실촬영 실내 화재) — 주 대상.
- New_sample (750장·AI-Hub·야외) — 후순위.
- **육안 감사 통과**: Indoor은 실촬영이고 라벨 신뢰할 만함(nofire=연기·미스트 등 하드네거, fire=박스가 실제 불꽃). 단 **주방/유류 아닌 일반 실내 화재**(도메인 부분 일치).

**분할·분량 (실험 A 학습/평가용)** — 임의로 나눈 게 아니라 **데이터셋(Roboflow export) 제공 분할을 그대로 사용**(랜덤 프레임 단위 70/15/15). **fire-only 재구성**으로 smoke 라벨을 제거하고 fire만 남겨(빈 라벨 = 음성) 합성 모델과 **1클래스로 공정 비교**:

| 분할 | 비율 | 장수 | 구성 | 용도 |
|---|---:|---:|---|---|
| train | 70% | 3,500 | fire + nofire | yolov8s 파인튜닝(학습) |
| valid | 15% | 750 | fire + nofire | 모델선택·조기종료 기준 |
| test | 15% | 750 | **fire 392 · nofire 358** | 최종 frame-level 지표(학습·튜닝 **불가침**) |
| **합계** | 100% | **5,000** | — | — |

> **비율은 문제 아님:** 70/15/15는 표준이고 절대 장수(train 3,500 · test fire 392 → recall 95% CI ±4.5%)도 충분해 바꿀 이유가 없다. **성능을 좌우하는 건 비율이 아니라 분할 '단위'**(프레임 랜덤분할 → 약한 누수)이며, 같은 test로 3조건을 상대 비교하므로 그 영향조차 결론을 흔들지 않는다.

- **비율은 적절**: 5000장에 70/15/15는 표준적. 특히 **val을 "실제" Indoor valid로** 둬서 회의 때 지적된 "합성 val 손해"(모델을 합성 기준으로 고르는 문제)도 해소.
- **한계**: 랜덤 **프레임** 분할이라 같은 영상의 인접 프레임이 train과 test에 갈릴 수 있음 → **약한 누수로 test 성능이 다소 낙관적**일 수 있음. 이상적 분할은 씬/영상 단위지만, 데이터셋이 프레임 단위로 제공돼 통제 못 함(§한계에도 기재).

**3. 깨끗한 첫 측정 (오염 없는 기준으로)**
기존 합성 모델을 Indoor Fire Smoke에 측정 → **recall 0.201 · precision 0.846 · fpr 0.040.**
- **낮은 recall은 진짜** (PSA 오염 탓 아님). **precision 높고 헛불 적음 → 문제는 놓침(recall).** 확정.

**4. 놓침 원인 진단**
놓친 이미지 육안(`_miss.jpg`): **크고 화면을 채우는 불·다양한 장면을 놓침.** → 합성이 **작은 불꽃 스프라이트(화면 15~45%)만** 얹어서 모델이 "작은 국소 불꽃"에 과적합 → **크고 다양한 실제 불을 못 알아봄.** (작은 뚜렷한 불은 잘 잡아 precision 높음.) **고칠 수 있는 병목.**

![Indoor 깨끗한 셋에서 놓친 큰/다양한 불 예시](img/indoorfire_missed_examples.jpg)

> **그림.** 깨끗한 Indoor Fire Smoke 셋(오염 없음)에서 **놓친(conf 0.00) 프레임 예시.** 화로 불·TV뉴스 주방 스토브 화재(ROCKVILLE MD)·거실 화염, 그리고 대비로 아주 작은 성냥불까지 — **크고 화면을 채우거나 장면이 다양한 불을 놓치고, 반대로 극단적으로 작은 불도 놓친다.** 작은 국소 불꽃 스프라이트만 학습한 결과와 정확히 맞는 실패 패턴.

**5. 실험 A — 합성 vs 실제 vs 혼합 (완료)**
"**실제 화재를 학습에 넣으면 놓침이 줄어드나?**" 직접 검증.
- 데이터: Indoor Fire Smoke fire-only(1클래스), 70/15/15 = train 3500 / valid 750 / **test 750(fire 392·nofire 358)**.
- 3조건 · **같은 실제 test**: ① 합성-only(기존 v8_C0_s1) · ② 실제-only(Indoor train) · ③ 혼합(합성 synth_C0 + Indoor train). val=실제(Indoor valid) · 각 60 epochs.
- 지표: frame-level recall/precision/fpr.

## 결과 (A) — 데이터셋 기본 랜덤 프레임 분할
> *지표: **recall** = 실제 불 중 검출한 비율(놓침의 반대·높을수록 좋음) · **precision** = 검출한 것 중 진짜 불 비율 · **fpr** = 불 없는데 오검출한 비율(오탐률·낮을수록 좋음).*

| 조건 | recall | precision | fpr | 검출(fire) |
|---|---:|---:|---:|---:|
| 1. 합성-only | 0.235 | 0.868 | 0.039 | 92 / 392 |
| 2. 실제-only | 0.985 | 0.990 | 0.011 | 386 / 392 |
| 3. 혼합 | 0.985 | 0.980 | 0.022 | 386 / 392 |

**판정 (방향):**
- **① → ②: 실데이터를 넣자 놓침이 사실상 사라짐** → **"놓침(recall) 병목은 실데이터로 고쳐진다"가 직접 확인됨.** 이 실험의 핵심 성과.
- **③ vs ②: recall 동일, 혼합이 precision·fpr 미세하게 나쁨** → **합성은 실데이터 위에 얹어도 기여 없음.** v1~v3의 "합성 전이 안 됨"과 일치.

## 결과 (B) — 누수 통제 재측정 (그룹 분할)
위 랜덤분할은 같은 영상 인접 프레임이 train·test에 겹치는 **누수**가 의심돼, 근접중복(dHash) 클러스터를 감사·통제해 재측정했다.
- **누수 감사**: test fire 프레임의 **73%(286/392)** 가 train에 근접중복 존재 → 누수 심각 확인.
- **그룹 분할 재측정**(클러스터가 split 한계 안 넘게 재분할 · test 근접중복 0 · 각 60ep):

| 조건 | recall | precision | fpr | 검출(fire) |
|---|---:|---:|---:|---:|
| 1. 합성-only | 0.237 | 0.842 | 0.041 | 85 / 358 |
| 2. 실제-only | **0.899** | 0.979 | 0.018 | 322 / 358 |

**판정 (보정):**
- **실제-only recall 0.985 → 0.899**: 누수가 약 **8.6점** 부풀렸으나, **보정 후에도 0.899로 견고** → 향상(0.237→0.899)의 **대부분은 진짜**.
- **합성-only 0.235 → 0.237로 불변**: 합성 모델은 Indoor 미학습이라 분할 방식에 영향 없어야 정상 → **불변 = 감사·재분할 방법론 sanity 통과.**
- → **"실데이터가 놓침을 고친다"는 결론은 누수를 제거해도 강하게 유지된다.**

> **⚠️ 남은 한계 = 도메인 (누수는 해소됨):** 누수를 통제한 뒤에도 recall **0.899**로 실데이터 효과는 견고하다. 다만 0.899는 여전히 **같은 도메인(Indoor 일반 실내) test** 성적이다. → 다음 §6에서 **목표 도메인(유류화재)** 으로 검증.

**6. 도메인 이동 파일럿 — 진짜 유류화재(튀김유) test (완료)**
"일반 실화재로 배운 모델이 **목표 위험(유류화재)** 도 잡나?" 직접 검증.
- **test**: 유튜브/빌리빌리 소방 시연(튀김유·기름솥 화재)에서 **오염 검증 후 큐레이션** — fire 65장(**4개 독립 장면**) / nofire 14장(2장면). **학습(Indoor)과 완전히 다른 출처 → 누수 원천 불가.**
- **오염 방지**: 선택 프레임을 전수 육안 검증 → 검은 전환·발화 전·타이틀 카드·진행자·그래픽 불 프레임을 걸러냄(특히 인터컷 심한 1편은 통째 제외).

## 결과 (C) — 도메인 이동 (유류화재 파일럿) · frame-level (conf 0.25)
> *conf 0.25 = 검출 confidence 문턱값(정확도 아님) · 모든 실험 공통.*
> *scene_mean±std = 장면(영상)별 recall의 평균 ± 표준편차. 프레임 수 편향을 없애 장면을 동등 취급(유효 표본 = 장면 수) · std 작을수록 모든 장면에서 고르게 잘함.*

| 모델 | recall | precision | fpr | scene_mean±std |
|---|---:|---:|---:|---:|
| ① 합성-only | 0.523 | 1.000 | 0.000 | 0.563±0.223 |
| ② 실제-only | **0.985** | 1.000 | 0.000 | 0.987±0.023 |
| ③ 혼합 | 0.985 | 1.000 | 0.000 | 0.987±0.023 |
| ②g 실제-그룹(누수통제) | **0.985** | 1.000 | 0.000 | 0.987±0.023 |

**판정:**
- **실데이터 모델이 진짜 유류화재에도 전이** — recall 0.985(64/65), 장면평균 0.987±0.023로 균일. **목표 도메인 첫 실증.** 합성은 0.523(장면 0.32~0.82)으로 약함.
- **③ 혼합 = ②g 그룹 = ② 실제** → 합성 무기여 재확인 + **누수통제 모델도 0.985.** 이 test는 학습과 다른 영상이라 **누수 원천 불가** → **0.985는 누수 없는 진짜 목표 성능.** (Indoor 같은-도메인 0.899 → 유류화재 목표 0.985: 오히려 높음 — 이유는 아래.)

> **왜 recall이 이렇게 높은가:** 절대값 0.985는 아래 요인이 겹친 결과다.
> 1. **크고 밝은 발화 후 화염** = 화재 검출에서 가장 쉬운 케이스. (그래도 합성-only는 0.523뿐 → 실데이터가 실화염을 진짜 학습한 것도 사실.)
> 2. **frame-level + 관대한 문턱(conf 0.25)**: 이미지에 박스가 하나만 잡혀도 성공(정밀 위치 아님 · 박스단위 val ~0.63보다 관대).
> 3. **장면 4개 · 프레임 근접중복**: 65장이라도 인접 프레임은 거의 동일 → 유효 N=4 장면.
> 4. **test가 발화 후 큰불에 치우침**: 선명한 화염만 양성으로 큐레이션, 초기·작은 불(어려운 케이스)은 제외.
>
> → "실데이터가 큰 유류화재를 잘 잡는다"는 **진짜 신호**이나, **배포 신뢰도 98.5%로 읽으면 안 된다.**

> **⚠️ 아직 확정으로 보면 안 되는 이유:** 장면 **N=4·음성 2장면** → **fpr 0.000·precision 1.0은 약한 증거.** 이 유류화재들은 **크고 선명한 발화 후 화염(쉬움)** — **초기·작은 불은 아래 §결과 D에서 별도 검증.** 시연 오버레이 잔존·**급식실 아닌 시연 세트**·정면 카메라 → 실제 급식실 시점은 더 어려울 수 있음. **소규모 파일럿의 방향성 신호**이지 배포 확정 아님.

## 결과 (D) — 초기·작은 불 (§C의 큰불 사각 보완) · frame-level (conf 0.25)
§C가 큰불에 치우쳐, **초기·작은 불꽃 프레임만** 따로 큐레이션(오염 전수 검증 · **파일럿과 공유 프레임 0** · 학습과 다른 출처라 누수 0) — fire 30장(4장면) / nofire 10장(연기·발화 전, 2장면).

| 모델 | recall | precision | fpr | scene_mean±std |
|---|---:|---:|---:|---:|
| ① 합성-only | 0.267 | 1.000 | 0.000 | 0.456±0.387 |
| ② 실제-only | **1.000** | 1.000 | 0.000 | 1.000±0.000 |
| ③ 혼합 | 0.967 | 1.000 | 0.000 | 0.983±0.029 |
| ②g 실제-그룹 | 0.967 | 1.000 | 0.000 | 0.983±0.029 |

**판정:**
- **실데이터 모델은 초기·작은 불도 거의 완벽 검출**(실제 1.000 · 혼합/그룹 0.967) → **§C의 미검증 사각(초기 불)이 검증됐고 양호.** 즉 일반 실화재 데이터가 유류화재의 **큰불(§C 0.985)·초기불(§D 0.97~1.0) 모두**에 전이.
- **합성은 초기 불에서 붕괴**(0.267 · 저해상 작은 불 ZDykV **0%**) — 작고 미묘한 불일수록 합성↔실제 격차가 극대화.
- 연기만(무화염) 10장에서 **헛불 0**(모델이 연기가 아니라 불꽃에 반응).

> **⚠️ 남은 한계:** 여기 "작은 불"은 **버너 위 뚜렷한 소형 화염**이지 **진짜 초기(첫 1~2초·아지랑이·연기만)** 수준은 아님. 장면 N=4·음성 2장면 → 방향성. 연기만 프레임엔 경보 안 함 = 조기경보를 더 당기려면 연기 탐지는 별도 과제. 급식실 시점·통제 촬영 검증은 여전히 필요.

## 결과 (E) — 하드네거티브 스트레스 test (헛불 검증) · frame-level (conf 0.25)
지금까지는 "불을 잡나(recall)"만 봤다. **"김·수증기·조리를 불로 오인하나(헛불)"** 를 재려고, 불 없는 정상 조리 영상 **130장(16개 독립 장면: 냄비 스팀·끓는물·대량조리·팬볶음·기름 가열·주방·식당 조명 등)** + sanity fire 10장으로 구성(오염 전수검증 = 불꽃 0 · 학습셋 무관).

| 모델 | sanity recall | **fpr(헛불률)** | 헛불 수 |
|---|---:|---:|---:|
| ① 합성 | 0.60 | 0.092 | 12/130 |
| ② 실제-only | 0.90 | 0.223 | 29/130 |
| ③ 혼합 | 0.90 | 0.238 | 31/130 |
| ②g 실제-그룹(누수통제) | 0.90 | **0.085** | 11/130 |

*precision은 음성130:양성10 편중 구성이라 왜곡 → **fpr로 판단.***

**판정:**
- **실데이터 모델이 헛불 문제를 노출** — real_only·mixed가 조리·스팀 장면의 **~22~24%에서 헛불**(배포엔 과함: 김에 4번 중 1번 우는 로봇).
- **누수통제 그룹 모델(②g)이 최선** — fpr **0.085**(real_only 0.223의 1/3) + recall 유지 → **불 잡기·헛불 억제 양쪽 다 좋은 유일한 모델.** dedup 학습이 덜 과적합 → 덜 trigger-happy(누수 통제의 부수 이득).
- **합성의 낮은 fpr(0.092)은 착시** — 애초에 불을 거의 못 잡아(recall 0.6) 검출 자체가 적을 뿐.

**헛불의 정체 (소스별 fpr):**
- **주황/따뜻한 조명**(식당 램프 13578888·13476222): real_only fpr **1.0·0.875** → **"불 색 착각"**.
- **어두운 배경 스팀**(8094275): real_only 0.667 → 검은 배경 연기 기둥을 불로 착각.
- 반대로 **순수 스팀 냄비**(267·대량조리 3967256·끓는물)는 대부분 **fpr 0.000** → **스팀 자체엔 안 속음.**

> **→ 고칠 수 있는 병목:** 헛불 내는 이 하드네거티브(주황 조명·어두운 스팀)를 **학습에 추가**하면 안 속게 됨. **급식실 화재 데이터 없이 precision을 개선하는 값싼 경로.** ⚠️ 경계: sanity fire 10장 소량 · 시연 오버레이 잔존. **→ 아래 §결과 F에서 실제로 시도했고, 결과는 "주황엔 무효"(데이터 문제 확정).**

## 결과 (F) — 헛불 고치기: 하드네거 재학습 (완료) · frame-level (conf 0.25)
§E에서 드러난 헛불(주황 조명·어두운 스팀)을 **그 하드네거티브를 학습에 음성으로 추가**하면 고쳐지나 검증. **급식실 화재 데이터 없이** precision을 개선하는 값싼 경로의 실측.

**설계 (누수 차단·일반화 증명):** 하드네거 130장(16장면)을 **장면 단위**로 train 12장면(87장) / held-out 4장면(43장)으로 분리 — 같은 영상 프레임이 train·test에 겹치지 않게(프레임 누수 0). held-out = `13476222`(주황)·`8094275`(어두운 스팀)·`94587527`·`267`. **핵심 설계 = 주황조명 일반화 증명:** 주황 장면 `13578888`(5프레임)**만** train에 넣고, **다른** 주황 장면 `13476222`를 held-out에 둬 "안 본 주황 장면에서 헛불이 주나"를 본다. train-hardneg 87장을 빈 라벨(음성)로 주입해 `real_only_hn`(랜덤분할)·`real_only_grouped_hn`(그룹·배포후보) 재학습.

**결과 (held-out 43장 fpr · 배포후보 그룹 모델 before→after):**

| 장면(프레임) | ②g 그룹(전) | ②gh 그룹_hn(후) |
|---|---:|---:|
| 13476222 주황조명(8) | 0.875 | **0.875** ← 안 변함 |
| 8094275 어두운스팀(12) | 0.000 | 0.000 |
| 94587527(11) | 0.182 | 0.091 |
| 267(12) | 0.000 | 0.000 |
| **전체(43)** | **0.209** | **0.186** |
| 목표 recall (pilot / early) | 0.985 / 0.967 | 0.985 / **1.000** |

**판정 = 사실상 무효:**
- 전체 fpr 미세 개선(0.209→0.186)은 전부 94587527 **1프레임**(2/11→1/11) = 노이즈 수준.
- **주황(13476222)은 모든 실모델에서 0.875~1.0로 요지부동** — `13578888`(주황 1장면·5프레임) 학습이 다른 주황 장면에 **전이 안 됨.**
- 스팀(8094275)은 그룹 모델이 hardneg 없이도 이미 fpr 0 → 애초에 hardneg 불필요.
- **목표 도메인 recall은 유지·오히려 향상**(early 0.967→1.000) → 헛불 억제가 진짜 불 검출을 해치진 않음. (Indoor recall만 0.899→0.821 하락 = 유류엔 전이 안 됨, 무시 가능.)

> **→ "주황조명 헛불 = 데이터 문제" 확정.** 다양성 있는 유형(스팀)엔 hardneg가 통했지만, train에 **주황 장면이 단 1개**뿐이라 다른 주황엔 일반화 못 함(사전 경고한 "1장면뿐 유형" 한계의 실증). **다음 레버 = 주황 조리 하드네거 장면을 여럿 수집**해 재학습(단일 장면 → 다수 장면). 그 전에 진단: `13476222`가 진짜 주황 불꽃 유사인지 단지 조명인지 **예측박스 몽타주**로 육안(`colab_diag_hardneg.py`).

**부수 확인 — 에폭 과적합 없음(자주 나오는 오해 차단):** 60ep 상한이 과적합을 부르지 않음이 이 재학습들에서 직접 확인됐다.
1. **val 이 하락 없이 평탄**(과적합이면 꺾여야 함).
2. **조기종료·best.pt 작동** — `real_only_grouped_hn` 은 **ep59 조기종료 → best=ep44 체크포인트 선택**(60 을 다 쓰지 않음).
3. **평가·배포엔 마지막 epoch 이 아니라 `best.pt`(val-best) 사용.**
→ **에폭 과적합은 음성(닫힌 질문).** 단 이 "과적합 없음"은 **학습 도메인(Indoor) 기준**이고, 위 주황조명 일반화 실패는 과적합이 아니라 **도메인 갭**(데이터로만 고침). 상세 `PREREGISTER_v2.md §5.7`.

**진단 — 주황 헛불의 정체 (예측박스 몽타주 `colab_diag_hardneg.py`, 2026-08-24).** "주황이 왜 안 고쳐지나"를 눈으로 확인하려 3개 주황 장면에 모델(`real_only_grouped_hn`) 예측박스를 얹어 봤다.

| 장면 | 모델이 불로 본 것 | 헛불 프레임 | 성격 |
|---|---|---:|---|
| `13476222` (학습에 **안 본** 레스토랑) | 배경 **작은 따뜻한 장식 전구**(우상단 전구 무리·좌측 샹들리에) | **7/8** | 지속 헛불 |
| `13578888` (학습에 **본** 주황) | — | **0/5** | 완전 억제 |
| `94587527` | 1프레임 경계(conf 0.35) | 1/11 | 경미 |

- **정체 = 넓은 주황 조명이 아니라, 작고 밝은 "따뜻한 점광원 전구"**(에디슨/장식 전구)가 소형 화염처럼 보이는 것. 박스가 전부 작고(면적 1%대) 전구 위치에 고정. 실제 불·로고·워터마크 아님.
- **기계적 확증**: 학습에 넣은 주황 장면(13578888)은 **완전 억제(0/5)** = 모델이 "이 전구=불 아님"을 배울 수 있음. 그런데 **안 본 주황 장면(13476222)엔 전이 실패(7/8)** = **1장면·5프레임으론 일반 개념을 못 배움.** → 주황 헛불은 "못 죽이는 특징"이 아니라 **장면 다양성 부족 문제**(다양한 따뜻한-전구 장면을 모으면 고칠 수 있음 — 직접 증거).
- **✅ 결정됨 (2026-08-24, 제품 범위 = 급식실 전용): 주황-전구 헛불은 out-of-domain → 저순위(수집 안 함).** 배포 대상 **학교 급식실 주방은 밝은 산업용 형광등**이라 주황 장식 전구를 쓰지 않는다(13476222 는 고급 레스토랑 무드조명). 따뜻한-전구 하드네거를 모아 재학습하면 **배포에 안 나올 지표만 최적화**하는 셈 → 하지 않는다. (참고: 제품이 일반 상업주방까지 넓어지면 그땐 in-domain 이 되어 재개할 값싼 카드 — 위 "다양성 부족" 증거로 확실히 효과 있음.)
- **★ 부수 함의 = 배포 도메인에서 헛불 문제는 raw 수치보다 작다.** §E/§F 의 fpr(그룹 0.085/held-out 0.209)은 **out-of-domain 장면(레스토랑 무드조명 13476222)이 최대 기여자**다. 그걸 빼면 **배포-대표 유형(밝은 주방·스팀·조리)에서는 그룹 모델이 이미 양호**(순수 스팀·끓는물·대량조리 fpr 0.000, 어두운 스팀도 그룹은 0). → **급식실 배포 관점의 실제 헛불률은 보고된 값보다 낮다.** 남은 진짜 과제는 헛불이 아니라 **배포-대표 양성 데이터**(급식실 주방 실화재 → A안 전이학습).

**→ 다음: frame-level 실화재 test 구성 → 현재 모델(`real_only_grouped`) 재측정(A안 ④) → 필요 시 fine-tune(⑤).**

## 한계
- **누수는 측정·통제됨(§결과 B).** 랜덤분할 0.985는 약 8.6점 부풀었으나 그룹분할 보정 0.899로 결론(실데이터가 놓침 해소)은 견고. → **남은 한계는 누수가 아니라 도메인.**
- **도메인 이동은 파일럿으로 확인(§6): 큰불(§C)·초기작은불(§D) 모두 실데이터 전이 양호.** 단 **장면 N=4**·**진짜 초기(첫 1~2초·아지랑이·연기만)·급식실 시점은 여전히 미검증.**
- **헛불(precision)은 §결과 E에서 검증: 실데이터 모델이 주황 조명·어두운 스팀에 헛불(fpr ~0.22, 누수통제 그룹은 0.085).** 순수 스팀엔 안 속음.
- **헛불 고치기(§결과 F)는 시도했으나 무효: 하드네거 재학습이 스팀엔 통하나 주황엔 요지부동(0.875) → 주황조명 헛불은 학습추가가 아니라 "주황 장면 다양성(데이터)"이 관건으로 확정.** 남은 사각 = 주황 하드네거 다수 수집·진짜 초기(아지랑이). **참고: 에폭 과적합은 이 재학습들에서 음성 확인(val 평탄·조기종료 ep44·best.pt) — 남은 건 과적합 아닌 도메인 갭.**
- Indoor Fire Smoke는 **일반 실내 화재(주방/유류 아님)** → "실데이터가 실화재 recall 올리나"는 답하나 **급식실 성능은 여전히 별개**(급식실 실화재 자료 부재).
- 그룹 분할은 dHash 근접중복 기반이라 **"인접 프레임 누수"** 를 제거함(진짜 영상 단위 분할의 근사). ham_thresh=6.
- 지표가 **frame-level recall**(이미지당 박스 1개만 잡혀도 성공)이라 박스단위(학습 중 val ~0.63)보다 관대 → 절대 recall을 다소 높게 보이게 함(방향 비교엔 영향 없음).
- 기존 realfire(PSA)는 오염 → 절대 수치 신뢰 불가(상대 비교는 견고).

## 미팅 피드백 이행 점검 (지난 미팅 체크리스트 대조)

지난 미팅 피드백 체크리스트를 현재 진행과 대조. **진단·방법론 피드백은 충실히 이행했고 그게 핵심 발견을 만들어냈다. "합성이 문제"라는 짐작도 데이터로 확증.** 다만 합성을 *고치는* 처방(에폭↓·생성형)은 우리가 "합성 대신 실데이터"로 피벗하며 일부 무의미해졌다.

| 미팅 피드백 | 상태 | 근거 / 비고 |
|---|---|---|
| yolo8 or yolo11 | ✅<br>부합 | YOLOv8s(v11 미러 확인) |
| Roboflow / Label Studio | 🟡<br>부분 | 데이터는 Roboflow(Indoor Fire Smoke) 확보 ✓ · Label Studio 미사용 |
| val=test 동일·하이퍼 재세팅 → 합성이 문제일듯 | ✅<br>결론 부합 | "합성이 문제" **직접 확증**(§5·§B: 실데이터 recall 0.235→0.985, 합성 무기여). 단 **문자 그대로 val=test 는 누수라 안 함** — "val 을 실제로"(Indoor valid) 잡는 올바른 해석으로 수행 |
| 디버깅: 감지 성공 vs 실패 모아 어디 아픈지 판단 | ✅<br>정면 부합 | **(핵심 축)** error-analysis(평가셋 오염 발견)·`_miss.jpg`(큰 불 놓침)·**§F 예측박스 몽타주(주황 전구 헛불 정체)** |
| epoch 마다 val·train loss 측정 | ✅<br>부합 | results.csv·show_curves(train/val loss+best epoch) → 오버피팅 분석에 사용 |
| 프레임 중복 많으면 문제 | ✅<br>정면 부합 | dHash 근접중복 감사(test 73% 누수) → 그룹 재분할 통제(§B) |
| 에폭 다시 잡기(10 이하, ex.6) | 🔴<br>미이행 | 60ep 유지(프로브상 val 정점~55). **오버피팅 아님**: val loss/mAP 가 하락 없이 평탄 · 평가·배포엔 `best.pt`(val-best 체크포인트) 사용 · patience 조기종료 작동. "6에폭이 전이에 더 나은가"는 별개 질문(미검증)이나, 실데이터 피벗 후 60ep 이 잘 돼(recall 0.985) 우선순위↓ |
| 데이터 다양성↑(지금은 어려움) | 🟢<br>상당 진전 | **실데이터 수집 실행(2026-08-25)**: 유류/주방 화재 영상 69개 수집·전수 검수 → 깨끗한 **28장면**(실제 상업·가정·**단체급식류 주방 CCTV** + NIST lab 실화재). fine-tune 문턱 충족. "급식실 실화재 자료 부재" 벽을 **공개 소스(Bilibili·NIST 등) 수집으로 상당 부분 우회**. 상세 `DATA_collection_spec.md §11`. (경계: 급식실 그 자체 실화재는 여전히 없음 — 근접 도메인으로 대체) |
| 생성형 AI(gpt-image/nano-banana)→Seedance/힉스필드 영상 | 🟡<br>후순위 | 실데이터 28장면으로 fine-tune 문턱 충족 → 생성형은 **그것으로도 부족할 때의 백업 카드**로 후순위 이동(실촬영 급식실 부재 시 보강용, 실제 test로 검증 전제) |

> **정직한 미이행 1건 + 대체 1건**: ① "에폭 ~6" — 우리가 답한 건 "60ep 이 val 에 과적합 안 함"이고 멘토 가설은 "*적은 에폭이 전이에 더 낫다*"라 **다른 질문**(미검증·저순위). ② **생성형 데이터** — 미착수이나 **실데이터 수집(28장면)으로 데이터 문제를 우선 해결** → 생성형은 부족 시 백업으로 후순위.
> **★ "데이터 다양성" 피드백은 이번에 실행으로 대응**: 미팅 땐 "지금은 어려움"이었으나, 이후 공개 소스(Bilibili·NIST 등)에서 실 주방/유류 화재를 수집·검수해 28장면 확보(§ 아래 "A안 데이터 수집" 참조).
