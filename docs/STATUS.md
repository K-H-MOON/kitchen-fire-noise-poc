# 현재 진행 상황 — "합성 대신 실데이터" 방향 (갱신)

배경: v1~v3(합성 학습)이 실제 화재에 전이 실패 → 병목 = 데이터/도메인으로 확정. 이후 방향을 실제 데이터로 전환.

## [완료]

**1. 평가셋 오염 정리** — 기존 realfire가 편집 소방 PSA(자막·PIP·만화 불)로 오염됨을 발견 → 폐기, 깨끗한 실데이터로 전환.

**2. 실데이터 투입 검증** — 실화재를 학습에 넣자 놓침 해소(recall 0.235→0.985), 근접중복 누수 통제 후에도 0.899로 견고. 합성은 무기여 재확인.

**3. 도메인 이동 확인** — 일반 실화재로 배운 모델이 유류(튀김유) 화재의 큰불·초기불 모두에 전이(0.985 / 0.97~1.0).

**4. 헛불 검증·고치기(주황조명)** — 주황조명 헛불은 급식실에 없는 out-of-domain(저순위), 배포도메인 헛불은 관리됨. 에폭 과적합 아님도 확인.

**5. A안 데이터 수집** — 유류/주방 화재 69영상 수집·전수 검수 → 깨끗한 28장면(상업·가정·단체급식류 주방 CCTV + NIST lab 실화재) 확보, 수집 종료.

**6. 현재 모델 재측정** — 채택 실화재로 frame-level test 구성·측정. **양성 프레임 오염(교육·실험 영상의 예열·안전텍스트·잔해)을 발견·교정**한 뒤: 배포후보 recall **0.813**(장면평균 0.846), 깨끗한 실화재 **13/16 장면이 0.72~1.0**. → **recall은 추가 학습 없이 이미 쓸 만.** 단 이 측정이 **로드맵에 없던 진짜 병목을 드러냄 = 정상 조리에 헛불(fpr 0.26).**

**7. 헛불 진단 + 전이학습(fine-tune)** — 예측박스로 헛불 원인 확인: 전부 **비화염**(불색 조리음식·스팀·스테인리스 반사, 실제 불꽃 아님). → 급식실 조리 영상을 **하드네거티브로 fine-tune** → 프레임 헛불 대폭 감소(안 본 급식실에서도 0.459→0.066).

**8. 생성형 데이터 보강 — 실행 안 함 (발동 조건 미충족)**
원래 8번은 **"7의 실데이터만으로 부족할 경우에 한해"** 발동하는 **조건부** 항목이었음. 그런데 **실데이터로 두 축이 모두 해결**되어 조건이 성립하지 않았음 — 놓침(recall)은 실화재 학습으로(2·6번), 헛불(fpr)은 실 급식실 조리 네거티브로(7번). 즉 **"실데이터 부족"이라는 발동 조건이 안 걸려 실행할 필요가 없었던 것**(못 한 게 아니라, 안 해도 됐다는 좋은 결과). 덧붙여 생성 데이터는 **"검증"에는 못 씀** — 합성으로 실제 성능을 증명하면 순환논리이고, v1~v3에서 이미 "합성→실제 전이 약함"을 확인했기 때문(학습 보강용으로만 제한적·성능은 반드시 실제 화재로 검증).

**9. 배포 성숙 검증(배경·시간축·교차-주방)**
- **배경격리(A)**: 급식실 배경은 실불꽃 검출을 **막지 않음**(병목은 불↔불색음식 외형 모호성).
- **시간축(B)**: 프레임 판정 → **화재 이벤트 경보**(지속성 K-of-N). 진짜 불은 지속·조리 헛불은 순간 깜빡 → 걸러짐.
- **교차-주방 검증**: 28영상 = **13개 학교 급식실.** 사이트(학교) 단위 leave-out + 이벤트-level(길이 독립 "헛경보/분")로 정직 검증.

→ **핵심 결론: 본 급식실 헛경보 ~0.2/분(recall 0.957) = per-site 보정 작동 vs 안 본 급식실 1.465/분(~7배) = 범용 one-model 미해결.**

## [미완료 / 향후]

- **범용화(안 본 급식실에 one-model 배포)** — 미해결. 필요: 학습 사이트 다양성↑ · 시간축 "모델"(외형이 아닌 불의 움직임·성장을 학습) 등. *(사이트 전체학습·시간축 모델은 기존 데이터로 가능하나, 진짜 범용화는 새 주방 데이터 필요.)*
- (조건부) **LOSO 전체 교차검증**(rigor·보고용, 기존 데이터로 가능·계산 고비용) · **박스단위 탐지**(로봇이 불 위치로 대응해야 할 경우, 기존 프레임 라벨링) · **실 급식실 화재 직접 검증**(데이터 확보·통제 실연 모두 불가 → 배경격리·시간축으로 갭을 좁히되 직접 증명은 보류).

## [한계]

**① 실 급식실 화재 부재 — "삼각측량"이지 직접 증명 아님.**
궁극 목표는 **"급식실에서 난 실제 유류 화재"를 잘 잡는가**인데, 그런 영상은 존재하지 않음(구할 수도·안전하게 실연할 수도 없음). 그래서 목표를 **두 축으로 나눠** 검증함:
- **불(양성) 축** — 실제 유류/주방 화재(단, 급식실 아닌 식당·가정·NIST 실험실) → "실제 불을 잡는가"(recall 0.81).
- **장면(음성) 축** — 실제 급식실 조리 영상(불 없음) → "급식실 정상 조리에 헛불을 안 내는가"(헛불 통제).

**배포 목표 = 이 둘의 교집합(급식실 × 실화재)** 인데 그 교집합을 직접 찍은 데이터가 없어서, **양옆 두 측정으로 가운데(목표)를 미루어 추정** — 이게 "삼각측량"(측량에서 두 지점 각도로 미지의 한 점을 구하듯). **직접 증명이 아닌 이유**: 교집합엔 두 축이 못 담은 조합(급식실 유류불 특유의 연기·스테인리스 반사·그 조명의 불꽃 외형)이 있을 수 있어, 두 축을 다 통과해도 **강한 정황이지 확정은 아님.** → 삼각측량 + (배경격리·시간축으로 갭 축소)로 확신을 최대한 끌어올리되, 직접 증명은 데이터 부재로 보류함을 명시.

**② 그 밖의 경계**: 지속되는 불색 음식은 시간축도 못 죽임 · 창백 극소형불 놓침 · 검증 표본 작음(사이트별 소수 영상·CI 큼).

## 한 줄 요약

실측 완료(recall은 이미 OK) → 진짜 병목은 "정상 조리 헛불"로 판명 → 조리 네거티브 fine-tune + 시간축으로 해결(본 급식실 헛경보 ~0.2/분) → **배포는 "새 급식실마다 그 주방 조리 학습"(per-site 보정)이 현실 경로, 범용 배포는 향후 과제.**
