# 사전 등록 v3 — 표현/백본 축 (DINOv3) · Phase 0 프로브

> **상태: Phase 0 계획·미착수 (2026-08-22).** 결과를 보기 전에 확정하는 문서.
> 여기 적힌 설계·성공 기준은 결과를 본 뒤 바꾸지 않는다. 바꿔야 할 근거가 생기면
> **바꿨다는 사실과 이유를 남긴 채** 바꾼다. v2 결론은 [PREREGISTER_v2.md §10·§11](PREREGISTER_v2.md).

## 0. 배경 — v2가 남긴 것

v2 Phase 1 = **음성 (C3 ≈ C0).** 불꽃을 실사 아틀라스+발광 합성으로 바꿔도 realfire 전이가
안 올랐고(§10), ablation은 **모델이 합성 분포 안에선 불꽃을 제대로 쓴다**(flame 0.94 ≫ bg 0.00)를
확정했다. → 병목은 **불꽃의 현실성·다양성이 아니라 그 바깥**(배경·씬 도메인갭 · 표현/백본 · temporal).
팀 제안 triage(§11)상 남은 실질 레버는 **DINOv3(표현/표상 축)**.

## 1. 질문과 가설 (정직하게)

- **가설**: YOLO가 배운 표현이 합성 분포에 과적합돼 전이가 안 됐다면, **실제 이미지로
  사전학습된 파운데이션 ViT(DINOv3) 표현은 합성→실제 전이가 YOLO보다 낫다.**
- **성공을 전제하지 않는다.** 반대 가능성도 명시:
  - 불은 **저수준 단서**(색·발광·질감)라 DINO의 *고수준 의미 특징*이 반드시 낫지 않을 수 있음.
  - 병목이 표현이 아니라 **데이터·씬 커버리지·temporal**이면 백본을 바꿔도 안 오름.
- **DINOv3는 탐지기가 아니라 백본**이다. 성능 향상은 가설이지 보장이 아니다.

## 2. 왜 Phase 0가 "프로브"인가 — 비용 방어

전면 탐지기 재구축(백본 교체 + 탐지 헤드 학습, pre-reg §"(A)") 전에, **핵심 질문
("표현이 전이가 나은가")만 싸게 단독 검증**한다. 탐지 헤드를 학습하면 "표현 덕"과
"헤드 학습 덕"이 섞여 원 질문이 흐려지므로, **백본을 고정(freeze)**하고 그 위에
**선형 프로브/kNN**만 얹어 표현 축을 단독으로 잰다.

- Phase 0 양성 → (A) 고정백본 탐지기 착수 정당화.
- Phase 0 음성 → 표현 축 아님 → 배경·씬·데이터·temporal로 피벗(무거운 백본 투자 회피).

## 3. 설계 — 단일 변수 = 표현(representation)

**과제(프로브):** 이미지/프레임 단위 **불/무 이진 분류** (탐지 recall의 proxy).
**변수:** 표현 추출기(백본)만 바꾼다. 전처리·프로브·데이터·평가 프로토콜은 고정.

**비교 백본 (전부 고정·frozen):**
1. **DINOv3** (후보). 접근 불가 시 **DINOv2 폴백** — "파운데이션 ViT 특징이 전이가 나은가"
   가설은 DINOv2로도 검증됨. 어느 걸 썼는지 결과에 명기.
2. **YOLO(합성 파인튜닝) 백본** = `v8_C0_s1` 임베딩 — **실제로 전이에 실패한 그 표현**(핵심 대조).
3. **YOLO(COCO 프리트레인) 백본** = `yolov8s.pt` — 일반 탐지기 표현 참조.
4. **ResNet50(ImageNet)** — 일반 실제-프리트레인 CNN 참조(DINO 특이성 vs 임의 프리트레인 분리).

## 4. 누수 차단 (v2 §2·§4 계승)

- **학습(fit)은 합성으로만**: `synth_C0/train`(라벨 있음=양성 / 빈 라벨=음성). C0=v1 기준선.
- **전이 시험은 realfire로만**: 학습에 안 쓴 불꽃 + 안 쓴 장면(참 sim2real).
- 프로브 임계값·하이퍼는 **synth val로만** 보정 — realfire로 튜닝 금지(held-out 오염 방지).

## 5. 지표 (v2 §6 계승 — 의사반복 방지)

- **주 지표: realfire AUROC**(fire vs nofire) — 임계값 무관 전이 품질. **영상 단위**로
  per-video AUROC + 풀링 + 군집 CI(t, df=영상수−1). 프레임 상관 → 의사반복 금지.
- **부 지표(해석용)**: synth-val 보정 임계값에서 realfire **recall·fpr**(YOLO flame_rate/fp_rate와 비교 가능).
- **견고성**: 선형 프로브와 **kNN**이 같은 방향인지.
- **가드(sanity)**: synth-val in-distribution AUROC ≥ 0.90 — 미달이면 특징 추출이 깨진 것(판정 보류).

## 6. 성공 기준 (실행 전 확정 · 결과 봐도 안 바꿈)

주 판정 = **realfire AUROC, DINOv3(또는 폴백) vs YOLO(합성) 프로브**. ΔAUROC = DINO − YOLO_synth.

- **GO (표현 축 유력)** = ΔAUROC ≥ **+0.10** **그리고** (per-video 방향 ≥ **4/5** DINO 우세 **또는** CI 비겹침).
  → 표현이 도메인-강건 불 신호를 담음 → (A) 고정백본 탐지기 착수 정당화.
- **NO-GO (표현 축 아님)** = |ΔAUROC| < **0.05** (노이즈 내). → 병목 표현 아님 → 배경·씬·데이터·temporal 피벗.
- **애매** = 0.05 ≤ ΔAUROC < 0.10 또는 CI 겹침. → 방향 지표로만, 팀과 판단(추가 검증·n↑).
- **선행 조건**: sanity 게이트(§5) 통과 시에만 위 판정 유효.

## 7. 정직한 경계 (과장 금지)

- 프로브는 **분류 전이 proxy**지 최종 **탐지 성능**이 아니다. GO는 "탐지기를 만들 근거"이지
  "탐지 성능이 오른다"의 증명이 아니다.
- realfire 영상 5개 → CI 큼. **방향 지표**이지 확정치 아님.
- DINOv3 ViT는 **무겁고 느림** — 실시간 조리로봇 배포엔 마이너스. GO여도 **이득이 배포 비용을
  정당화하는지는 별도 판단**.
- YOLO는 탐지기, 프로브는 분류 — 완벽한 등가는 아니나, **모든 백본을 동일하게 "고정 특징 + 동일
  프로브"로** 재므로 표현 축 비교로는 공정하다.
