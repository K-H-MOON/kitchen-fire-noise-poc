# 실제 화재 데이터 수집 사양 (신규 방향, 2026-08-24)

> 병목 = 데이터/도메인(합성↔실제 간극). 이를 좁히려 **실제 화재 데이터**를 모은다. 무작정 모으면 일반 불(산불·건물)만 쌓여 걸러낼 게 많으니, **무엇을·얼마나·어떻게** 미리 못박는다. (pre-reg v3 §5.1 확장 · 용도·분할은 [HANDOFF](HANDOFF.md) "회의 후 신규 방향" 참고)

## 0. 용도별로 실제/생성이 다르다
| 용도 | 쓸 수 있는 데이터 |
|---|---|
| **val / test** (모델 선택·전이 측정) | **실제만** (생성 데이터는 자기순환 → 금지) |
| **train** (도메인갭 축소) | 실제 + (보강) 생성형 AI |

→ **"실제 val 확보"가 목표면 실제 수집이 유일한 길.**

## 1. 무엇을 — 도메인 (가까울수록 좋음)
두 축: **① 불 종류(유류 우선) · ② 장면(실내 주방).**

| 등급 | 데이터 | 채택 |
|---|---|---|
| 이상적 | 급식실 유류/조리 화재 | 자료 부재(있으면 최우선) |
| **양호(현실적 대체)** | **일반 주방/튀김유 화재**(가정·식당·실험실) | ✅ **주 수집 대상** |
| 약함 | 산불·건물·모닥불·촛불 등 일반 불 | ❌ 제외(도메인 어긋남) |

## 2. 두 클래스 (+ 하드네거 필수)
- **fire**: **불꽃이 보이는** 주방/유류 화재 (연기만 있는 건 제외).
- **nofire**: **불 없는 주방/조리 장면** — 특히 **하드네거티브**(수증기·김·주황/빨강 음식·버너 불빛·반짝이는 기름) 포함. → precision(헛불) 시험용.
- ⚠️ nofire를 무관한 장면(풍경·사무실)으로 채우면 착시(AUROC 부풀림) → 금지.

## 3. 실사만
- ❌ 합성·CG·AI생성·만화 (val/test엔 절대. train 보강용 생성은 별도 관리).
- ❌ fire=어두움 / nofire=밝음 식의 밝기 교란(모델이 밝기로 맞힘).

## 4. 얼마나 — 장면 다양성 > 장수
- **핵심 = 서로 다른 독립 장면(소스) 수.** 한 영상 수백 프레임은 의사반복이라 N을 안 늘림.
- **목표(권장)**: val·test를 겹치지 않게 나눌 만큼 → **독립 장면 각 ≥ 10** (합 ≥ 20~30). 현 realfire 5편은 val/test 분리에 부족.
- 소스별 폴더로 분리(장면=군집 단위).

## 5. 출처
- **실제 화재 영상**(YouTube 등 주방/튀김유 화재 실험·뉴스·데모) → 프레임 추출 (현 realfire 5편 방식, `real_fire.json`에 추가).
- **Roboflow Universe / Kaggle** 실사 화재 — 단 대부분 일반 불이라 **§1·§2 기준으로 골라내기**(검증용).
- (train 보강만) 생성형 AI — 실제로 착각될 품질인지 육안·프로브 선검증, generative artifact 주의.

## 6. 주석 (Label Studio 등)
- **프레임 단위 분류(fire/nofire)** = 최소 요건(현 프로브·recall/precision에 충분).
- **탐지 박스** = 최종 탐지기 평가·학습에 필요(여유되면).
- 주석자 기준 통일(불꽃 보이면 fire 등).

## 7. 분할 규칙 (누수 차단)
- **장면(소스) 단위로** train/val/test 분리 — 같은 영상이 두 세트에 안 들어가게.
- **val을 튜닝에 쓰면 test는 절대 안 건드림.** val=test 금지(누수).
- 실제를 val/train에 넣으면 "순수 sim2real 전이 측정"은 약해짐(실전 성능 지향으로 전환됨) — 의도 명시.

## 8. 수집 시 체크리스트
- [ ] 주방/유류 화재인가? (산불·건물 아님)
- [ ] 불꽃이 실제로 보이나? (fire) / 무화재 주방 + 하드네거 포함하나? (nofire)
- [ ] 실사인가? (CG·AI 아님)
- [ ] 학습/기존 realfire와 중복 아닌가?
- [ ] 독립 장면 수가 val/test 나눌 만큼인가? (소스별 폴더)
- [ ] fire:nofire 균형(한쪽이 3배 초과 금지)

## 9. 무엇을 "더" 모을지 — error-analysis 결과 (2026-08-24, v8_C0_s1)

**1차 숫자(주의: 아래 육안에서 일부 정정됨):** 밝기별 miss율 어두움 48% → 중간 70% → 밝음 94% · 영상별 miss kanetsu 92% · hisomu 100% · jikken 66% · tokyo 62% · grease 46% · 헛불 grease 41% · 검출 conf 중앙 0.65.

**★ 육안 정정 (`_miss.jpg`, 2026-08-24):** "밝은 장면 놓침" 결론은 **오염 — 보류.**
- jikken 놓침 대다수가 **편집 다큐 프레임**(PIP 작은 실장면 + 자막 "発火" + **만화풍 노란 불 삽화**). "밝음"은 **실화재가 아니라 편집 그래픽의 밝기**였음. 모델이 가짜 만화 불을 안 잡는 건 정상인데 "fire" 라벨이라 miss로 집계됨.
- → **밝기-miss 상관은 편집 그래픽에 오염 → "밝은 실화재를 못 잡는다"로 읽지 말 것.**

**진짜 드러난 것:**
1. **실제 불꽃이 작다(초기 단계)** — 팬 속 불이 작은데 놓침 → "작은/초기 불꽃"이 유력 사각.
2. **평가 데이터 품질 문제** — jikken은 편집 다큐(PIP·자막·만화 불)라 배포 CCTV와 딴판 → realfire 점수를 부당하게 깎음.
3. kanetsu(92%)·hisomu(100%) 놓침은 **아직 미확인**(영상별 시트 필요) — 진짜 유류화재 실패인지 별도 판독.

**→ 잠정 수집·정비 방향:**
1. **깨끗한(편집 없는) CCTV류 주방/유류 화재** — 자막·PIP·만화 그래픽 없는 실촬영. **작은/초기 불꽃 포함.**
2. jikken류 **편집 다큐는 지양**(train·eval 모두 오염원).
3. **realfire 평가셋 재큐레이션 검토** — 편집 그래픽 프레임 제외(현 수치는 불리하게 편향).
4. kanetsu·hisomu 영상별 판독 후 사각 유형 확정.
