# 실제 화재 데이터 수집 사양 (신규 방향, 2026-08-24)

> 병목 = 데이터/도메인(합성↔실제 간극). 이를 좁히려 **실제 화재 데이터**를 모은다. 무작정 모으면 일반 불(산불·건물)만 쌓여 걸러낼 게 많으니, **무엇을·얼마나·어떻게** 미리 못박는다. (pre-reg v3 §5.1 확장 · 용도·분할은 [HANDOFF](HANDOFF.md) "회의 후 신규 방향" 참고)

## 0. 용도별로 실제/생성이 다르다
| 용도 | 쓸 수 있는 데이터 |
|---|---|
| **val / test** (모델 선택·전이 측정) | **실제만** (생성 데이터는 자기순환 → 금지) |
| **train** (도메인갭 축소) | 실제 + (보강) 생성형 AI |

→ **"실제 val 확보"가 목표면 실제 수집이 유일한 길.**

## 1. 무엇을 — 도메인 (가까울수록 좋음)
두 축: **① 불 종류(유류 우선) · ② 장면(실내 주방).**

| 등급 | 데이터 | 채택 |
|---|---|---|
| 이상적 | 급식실 유류/조리 화재 | 자료 부재(있으면 최우선) |
| **양호(현실적 대체)** | **일반 주방/튀김유 화재**(가정·식당·실험실) | ✅ **주 수집 대상** |
| 약함 | 산불·건물·모닥불·촛불 등 일반 불 | ❌ 제외(도메인 어긋남) |

## 2. 두 클래스 (+ 하드네거 필수)
- **fire**: **불꽃이 보이는** 주방/유류 화재 (연기만 있는 건 제외).
- **nofire**: **불 없는 주방/조리 장면** — 특히 **하드네거티브**(수증기·김·주황/빨강 음식·버너 불빛·반짝이는 기름) 포함. → precision(헛불) 시험용.
- ⚠️ nofire를 무관한 장면(풍경·사무실)으로 채우면 착시(AUROC 부풀림) → 금지.

## 3. 실사만
- ❌ 합성·CG·AI생성·만화 (val/test엔 절대. train 보강용 생성은 별도 관리).
- ❌ fire=어두움 / nofire=밝음 식의 밝기 교란(모델이 밝기로 맞힘).

## 4. 얼마나 — 장면 다양성 > 장수
- **핵심 = 서로 다른 독립 장면(소스) 수.** 한 영상 수백 프레임은 의사반복이라 N을 안 늘림.
- **목표(권장)**: val·test를 겹치지 않게 나눌 만큼 → **독립 장면 각 ≥ 10** (합 ≥ 20~30). 현 realfire 5편은 val/test 분리에 부족.
- 소스별 폴더로 분리(장면=군집 단위).

## 5. 출처
- **실제 화재 영상**(YouTube 등 주방/튀김유 화재 실험·뉴스·데모) → 프레임 추출 (현 realfire 5편 방식, `real_fire.json`에 추가).
- **Roboflow Universe / Kaggle** 실사 화재 — 단 대부분 일반 불이라 **§1·§2 기준으로 골라내기**(검증용).
- (train 보강만) 생성형 AI — 실제로 착각될 품질인지 육안·프로브 선검증, generative artifact 주의.

## 6. 주석 (Label Studio 등)
- **프레임 단위 분류(fire/nofire)** = 최소 요건(현 프로브·recall/precision에 충분).
- **탐지 박스** = 최종 탐지기 평가·학습에 필요(여유되면).
- 주석자 기준 통일(불꽃 보이면 fire 등).

## 7. 분할 규칙 (누수 차단)
- **장면(소스) 단위로** train/val/test 분리 — 같은 영상이 두 세트에 안 들어가게.
- **val을 튜닝에 쓰면 test는 절대 안 건드림.** val=test 금지(누수).
- 실제를 val/train에 넣으면 "순수 sim2real 전이 측정"은 약해짐(실전 성능 지향으로 전환됨) — 의도 명시.

## 8. 수집 시 체크리스트
- [ ] 주방/유류 화재인가? (산불·건물 아님)
- [ ] 불꽃이 실제로 보이나? (fire) / 무화재 주방 + 하드네거 포함하나? (nofire)
- [ ] 실사인가? (CG·AI 아님)
- [ ] 학습/기존 realfire와 중복 아닌가?
- [ ] 독립 장면 수가 val/test 나눌 만큼인가? (소스별 폴더)
- [ ] fire:nofire 균형(한쪽이 3배 초과 금지)
- [ ] 밝기·조명이 두 클래스 간 교란되지 않나?

## 9. 무엇을 "더" 모을지 — error-analysis 결과 (2026-08-24, v8_C0_s1)

**1차 숫자(주의: 아래 육안에서 일부 정정됨):** 밝기별 miss율 어두움 48% → 중간 70% → 밝음 94% · 영상별 miss kanetsu 92% · hisomu 100% · jikken 66% · tokyo 62% · grease 46% · 헛불 grease 41% · 검출 conf 중앙 0.65.

**★★ 영상별 육안 확정 (2026-08-24) — 평가셋이 오염돼 있었음:**
- **jikken·kanetsu·hisomu = 편집된 소방 홍보(PSA) 영상.** PIP·자막·타이틀 카드("天ぷら火災の消火方法 吹田市消防本部")·만화 캐릭터·말풍선·삽화 범벅. **"fire" 라벨 프레임에 실제 불이 없거나 그래픽에 가려짐** → 모델이 정당하게 안 잡은 걸 miss로 집계.
- **grease_spread 헛불(41%) = 헛불 아님.** 프레임에 **진짜 큰 불이 있는데 "nofire"로 라벨** → 정확 검출을 FP로 집계. **nofire 구간 라벨 오류.** (게다가 야외 구조물 화재 — 주방 아님)
- **"밝은 장면 놓침"은 완전 착오** — 그 "밝음"은 타이틀 카드·만화 배경·자막의 밝기였음.

**→ 결론: realfire recall(0.31·0.27 등)은 편집 프레임에 심하게 오염·과소평가된 값.** 모델의 실제 성능은 **아직 제대로 모름.**
- 상대 비교(C3≈C0·DINOv3 미미)는 같은 셋을 겪어 비교적 견고. **절대 주장("실제 인식률 낮음")은 신뢰 불가.**
- 가장 깨끗한 grease(야외 실화재) 54% 검출이 방증.
- 부차 가능성(미확정): kanetsu 큰 불이 자막 뒤에서 놓침·hisomu 거대불꽃 → "큰/벽 화재 과소검출"(학습 불꽃이 작은 합성) — 오염과 뒤섞여 미확정.

**★★★ 깨끗한 실데이터 판독 (Indoor Fire Smoke `_miss.jpg`, 2026-08-24) — 놓침 원인 확정:**
- **큰 불·화면 꽉 채우는 불을 놓친다** (방 전체 불길·벽 같은 화염 기둥·대형 주방화재). ← hisomu 거대불꽃 가설 확증.
- 다양한 장면·불 종류(화로·복도·거실·성냥불)·색 변이도 놓침.
- **진단**: 우리 합성 학습이 **작은 불꽃 스프라이트(화면 15~45%)만** 얹어서, 모델이 **"작고 국소적인 주황 불꽃"에 과적합** → **크고 다양한 실제 불을 못 알아봄.** (작은 뚜렷한 불은 잘 잡아 precision 0.85 높음.)
- **→ 고칠 수 있는 병목**: ① 합성에 **큰/화면 채우는 불꽃·다양한 크기** 추가 ② 실제 화재 데이터(크기·장면 다양)를 train에 투입.

**→ 우선순위 변경:**
1. **#1 = 깨끗한 realfire 평가셋 확보·재큐레이션** (편집 PSA·그래픽·자막·오라벨 nofire 제외 / 실촬영 CCTV류 주방·유류 화재로 교체). **지금 자로는 전이를 못 잰다 — 이게 최우선.**
2. 학습용도 **깨끗한(편집 없는) 주방/유류 화재** — 작은/초기 불꽃 + (검증할 것)큰 불 포함.
3. jikken류 편집 다큐는 **train·eval 모두에서 배제.**

*원 스크립트: `colab_realfire_erroranalysis.py`(영상별 시트) · 재현 `ERR_MODEL`. 시트: `err_analysis/_miss_<video>.jpg`·`_fp_<video>.jpg`.*

## 10. 유류/주방 화재 수집 사양 — A안(전이학습)용 (2026-08-24 확정)

**맥락.** §실험A~§F(→ `AFTER_meeting.md`) 결과: 실데이터가 놓침 해소·유류 파일럿 전이(0.985)·헛불은 배포 도메인에선 관리됨·주황 헛불은 급식실 out-of-domain(저순위). 남은 유일 갭 = **급식실-근접 도메인 성능**. 실촬영 급식실은 불가 → 공개 유류/주방 화재를 **소방 시연 + 상업 주방** 위주로 모아 A안(전이학습)의 fine-tune/test 데이터를 확보한다.

**수집 순서(합의됨) — test 먼저, 자기교정적:**
1. 유류/주방 화재 장면 수집 → **작은 실제 test + fine-tune 풀** 확보.
2. 그 실제 test로 **현재 모델(`real_only_grouped`) 먼저 재측정** → A안 fine-tune 필요/이득 판단.
3. **fine-tune 데이터가 문턱 미달이면** → test로 현재 모델 측정에 그치고 **(나) 생성형 데이터**(gpt-image/nano-banana→Seedance, 미팅 카드)를 **실제 test로 검증하며** 증강. ⚠️ v1~v3 sim2real 실패 이력 → 생성형은 소규모 증명부터.

**목표량(사전 문턱, 흔들림 방지):**
- **test 최소선**: 독립 장면 **≥ 10**(유류/주방 화재) + 음성 장면 몇 개(같은 주방류 배경의 정상 조리·스팀).
- **fine-tune 진입선**: 학습용 독립 장면 **≥ 20~25** → A안 fine-tune. 미만이면 위 3번으로 전환.

**최선 소스 = 소방 시연(YouTube·Bilibili) · 차선 = 상업 주방 화재 CCTV**(장비=급식실과 동일, 일반 실내 화재보다 급식실에 가까움). Roboflow/학술셋은 일반 화재 위주라 특이성 낮음(§5 참고).

**검색어:**
- 한국어: `튀김유 화재` · `식용유 화재 실험` · `튀김기 화재` · `기름 화재 소화` · `주방 화재 실험`
- 일본어: `天ぷら火災` · `天ぷら油 火災 実験` · `厨房 火災` · `油火災 消火実験` (⚠️ `吹田市消防本部` 류 편집 PSA는 §9 오염 소스)
- 영어: `kitchen grease fire` · `deep fryer fire` · `cooking oil fire experiment` · `pan fire test`
- 중국어(Bilibili): `油锅起火` · `厨房火灾` · `食用油 灭火 实验` · `油锅着火`

**담기/버리기(§9 오염 교훈):**
- 담기: 실제 기름/주방 화염이 **안 가려지고** 찍힘 · 카메라 비교적 고정 · 서로 다른 셋업.
- 버리기: 자막·타이틀카드·PIP·만화불이 **불꽃 덮은 편집 PSA** · 주방 아닌 화재 · **같은 원본 시연의 재업로드**(다른 채널 동일영상 = 누수).

**장면(scene) 단위 규칙(§7 강화):**
- **한 물리적 셋업/장소 = 1장면.** 같은 사건 카메라 앵글 여러 개는 1장면(근접중복).
- **출처 영상 ID를 파일명 prefix로 기록**(split·평가 스크립트가 prefix로 장면 가름).
- **기존 파일럿 장면과 비겹침**: 현 test에 `yt_BV1Ux4y1Z7z6`·`yt_ZDykVIW-5GY`·`yt_ZpoU_kwUoOU`·`yt_jkXLZ8cAdYY` 존재 → 새 수집은 **새 독립 장면**이어야 test 누수 없이 확장.
