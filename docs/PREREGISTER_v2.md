# 사전 등록 v2 — 합성 불꽃 현실성 개선

> **상태: 계획·미착수 (2026-08-20).** 결과를 보기 전에 확정하는 문서.
> 여기 적힌 결정·성공 기준은 결과를 본 뒤 바꾸지 않는다. 바꿔야 할 근거가 생기면
> **바꿨다는 사실과 이유를 남긴 채** 바꾼다. v1 결론은 [TIMELINE.md](TIMELINE.md) 참고.

## 0. 배경 — v1이 남긴 것

v1 결론: 합성 파이프라인이 **배경 지름길이 아닌 진짜 불꽃 검출기**를 만들고
(ablation 통과), 노이즈 강건성도 **아키텍처에 견고**하게 성립했으나, **실제 불 전이는
약함**(realfire 0.31, 하한). 육안 검수상 **합성 불꽃이 납작한 주황 "컷아웃"**처럼 보임
— 실제 불의 발광·입체감·주변 조명 스필이 없음(알파 오버 합성). 병목은 배경이 아니라
**불꽃의 현실성·다양성**으로 좁혀짐. **이건 가설(육안 corroborate)이지 실험으로 증명된
게 아니다.**

## 1. 목표와 가설 (정직하게)

- **가설**: v1의 약한 전이의 원인은 합성 불꽃의 **플랫·협소**다.
- **v2는 이 가설의 개선 시도이자 실험이다.** 현실적 불꽃으로 바꿔도 전이가 안 오르면,
  **병목은 불꽃이 아니었다**를 배운다. **성공을 전제하지 않는다.**
- **가장 무거운 사전지식**: 이전 저장소 [kitchen-fire-poc]는 **바로 이 실사 화염 아틀라스·
  절차적 셰이더를 갖고도 sim2real을 못 닫아 `미해결`로 종결**했다. 좋은 불꽃은
  **필요조건이지 충분조건이 아니었다**는 실측 사례. → v2도 "개선은 유력하나 해결은
  보장 못 함"으로 본다.

## 2. 핵심 원칙 — 착시 차단

이전 저장소가 지적한 **"같은 화염 텍스처, 다른 배경" 착시**(아틀라스를 학습에 쓴 실사
영상에서 뽑아 그 영상으로 시험 → 전이가 아님)를 원천 차단한다.

**검증은 반드시 "학습에 안 쓴 불꽃 + 안 쓴 배경"으로만 잰다.**

## 3. 단일 변수 A/B

불꽃 합성 방식만 바꾸고 나머지는 v1과 **완전히 고정**한다.
- **고정**: 급식실 배경·사이트 분할, 아키텍처(v8[·v11]), 합성 장수, seed 5개,
  eval 프로토콜, **realfire 검증셋(동일 shots)**, ablation.
- **변수**: 불꽃 = v1(플랫 4종) vs v2(아틀라스 390 + 발광 합성).

## 4. 누수 차단 — 3축 분리

1. **불꽃 소스 분리**: 학습 불꽃(아틀라스)과 realfire 검증 불꽃이 **한 영상도 겹치지
   않아야** 함.
   - 유리한 점: 아틀라스는 **범용 스톡 화염 11개**(모닥불·토치류)에서 뽑았고, realfire는
     **실제 튀김유 화재**다 → 소스 풀이 원래 다르다.
   - **소재 확보 상태 (2026-08-20)**: 아틀라스 스프라이트는 **kitchen-fire-poc repo `assets/flamelib`
     (WebP)에서 회수됨** — 재구축 불필요, 그대로 재사용. (Drive의 fire_project 데이터는 비어 있으나 repo에 살아있음.)
   - **사전 점검(필수)**: 아틀라스 소스(flamelib 원본 스톡 화염)를 realfire 영상(및 확장분)과 대조해
     **실제로 0 overlap** 인지 확인. (이전 아틀라스가 혹시 튀김유 영상을 포함했는지 검증.)
2. **배경 분리**: 사이트 단위 train/val/test — v1에서 확보됨, 유지.
3. **realfire = 두 축 모두 초면**: 학습에 안 쓴 불꽃 + 안 쓴 장면. 이게 참 sim2real.

## 5. 조건 C0~C3

**소재 카테고리가 아니라 실험 조건(레시피)이다.** 각 조건 = **(불꽃 소스 × 합성 방식)**
조합을 **한 번에 하나씩만** 바꿔 누적한 것. 인접 비교가 "무엇이 효과였는지"를 분리한다.

| 조건 | 불꽃 소스 | 합성 방식 | 직전 대비 바뀐 것 |
|---|---|---|---|
| **C0** (=v1) | 플랫 4종 | 알파 오버 | (기준선) |
| **C1** | 아틀라스 390 | 알파 오버 | ← **소스만** 교체 |
| **C2** | 아틀라스 390 | +가산 블렌딩·엣지 페더 | ← **합성 통합** 추가 |
| **C3** (=풀 v2) | 아틀라스 390 | +가짜 조명 스필 | ← **조명 스필** 추가 |

### 개념도 — 각 비교가 재는 것

- **C0 → C1**: "소재를 좋게(390·발광)" 만든 효과.
- **C1 → C2**: "붙이는 방식을 발광답게" 만든 효과.
- **C2 → C3**: "주변까지 밝히는(스필)" 효과.
- **C0 vs C3**: 전체 v2의 순효과 — **핵심 대비**.

> 단서: **C0→C1은 두 가지가 섞여 있다** — 소스 4→390(다양성) + 플랫→휘도키잉(스프라이트
> 현실성). 이 둘을 더 쪼개려면 조건을 추가해야 함(예: "아틀라스 4종만" / "플랫 390종").
> 지금 목적엔 과설계라 넣지 않는다. 다양성 vs 현실성 분리가 꼭 필요해지면 그때 추가.

### 5.5 합성 세부 결정 — 라벨 박스와 블렌딩 (결과 보기 전 확정, 2026-08-21)

C2·C3에서 발광·스필을 넣으면 두 가지가 새로 정해져야 한다. 결과 보기 전에 못박는다.

**(가) 라벨 박스 = 알파 bbox 고정.** 블룸·스필이 불꽃 경계 밖 배경을 밝혀도 정답
박스는 불꽃 매트 경계에 딱 맞춘다(넓히지 않음). 이유:
- **단일변수 보존** — 라벨 정의도 '고정' 대상이다. C0가 딱 맞는 박스, C3가 넓힌
  박스면 두 조건이 **합성 방식과 라벨 방식 둘 다** 달라져, 전이 변화를 불꽃 탓으로
  귀속할 수 없다.
- **realfire 채점 기준과 정합** — realfire 검증은 **불꽃 자체**를 박스로 잰다(불이
  비춘 주변 빛이 아니라). 학습 박스가 "빛 번짐까지" 넓으면 train↔eval 박스 정의가
  어긋나 **측정 전이가 억울하게 낮아진다**.
- **자동 주석 유지** — 스프라이트 경계 = 자동 정답(수작업 0)이라는 v1 장점을 지킨다.
  번짐까지 잡으려면 합성 결과에 문턱을 걸어야 하고, 그 문턱은 배경 밝기마다 흔들려
  주석 모호성이 재발한다.
- 한계: 박스 밖 번짐은 라벨 없는 신호로 남는다. 그러나 실제 불도 불꽃(물체)과 주변
  빛(맥락)이 분리되므로 자연스럽고, 검증 기준과 맞추는 이득이 더 크다.

**(나) 블렌딩 = 스크린 + 코어 블룸.** 알파 오버(v1) → **스크린**을 바탕으로 얹고,
가장 밝은 매트 영역만 흰색 쪽으로 살짝 가산(**코어 블룸**). 이유:
- **클리핑 방지** — 급식실 배경이 밝다(≈150+). **가산**은 255를 넘겨 순백으로 잘려
  색·계조를 잃은 흰 덩어리가 된다(색만 바뀐 컷아웃). **스크린**은 흰색에 부드럽게
  수렴해 불꽃 색과 그라데이션을 살린다 — v2 목표(납작함 탈피)에 직결.
- **우리 도메인에서 안전** — 어두운 영역에선 두 방식이 비슷하고, 차이는 밝은
  영역에서 난다. 급식실 배경이 바로 거기 있으므로 스크린이 항상 더 안전하다.
- **센서 물리 근접** — 실제 센서도 하이라이트를 무한정 더하지 않고 눌러 담는다
  (soft-shoulder). 스크린이 그 거동에 더 가깝다.
- 한계: 순수 스크린은 백열 코어가 밍밍해질 수 있다. **코어 블룸**으로 전역 클리핑
  없이 코어의 강렬함만 보완한다.

두 결정 다 **Phase 0(값싼 육안 검증, 재학습 없음)**이 안전망이다 — 방향만 정하는
것이고, 어색하면 학습 전에 되돌린다.

### 5.6 아틀라스 train/test 소스 분할 (확정, 2026-08-21)

아틀라스 390장은 8소스(v01 39·v02 4·v03 117·v05 19·v06 20·v07 136·v09 23·v10 32).
합성 test 의 불꽃을 **학습에 안 쓴 소스로만** 뽑기 위해(§2 텍스처 착시 차단) 소스 단위로 나눈다.

    train (348장·6소스)  v01 · v02 · v03 · v06 · v07 · v10
    test  ( 42장·2소스)  v05 · v09          ← held-out, 학습에 한 번도 안 씀

**왜 이 비율(≈89/11)인가 — 일방적으로 보이나 데이터에 맞춘 것:**
- **이미지 분할과 매칭.** train/test 이미지가 2,278/309(≈88/12)라, 불꽃 풀
  348/42(≈89/11)를 맞추면 **소재당 재사용이 양쪽에서 균형**(train ~3.9× · test ~4.4×).
  test 불꽃이 굶거나 혹사되지 않는다.
- **train-heavy 는 의도.** v2 목표가 불꽃 다양성으로 전이를 올리는 것이므로 학습에
  최대한 많은 소재를 넣는 게 이득. 소재를 test 로 빼면 정작 키우려는 다양성이 준다.
- **진짜 held-out 은 realfire.** 실제 유류화재(불꽃·장면 모두 초면)가 주지표이고,
  합성 test 는 보조 가드라 여기 소재를 많이 뺄 이유가 약하다.
- **큰 소스(v03·v07)는 train, 중간 소스(v05·v09)를 held-out.**

**한계:** 소스가 8개뿐이라 held-out 불꽃이 2계열(v05·v09)로 좁다. 합성 가드로는
충분하나, 합성 test 를 강한 독립 지표로 읽지는 않는다(그 역할은 realfire).

코드: `colab_synth.py` 의 `ATLAS_SPLIT`.

### 5.7 학습 epoch — 프로브 측정으로 확정 (60, 2026-08-21)

**질문.** v1 은 80 epoch. 멘토가 "변동이 크지 않으면 70~80 은 과하다"고 지적. 추측 대신
**측정**한다.

**프로브** (`colab_v2_probe.py`) — `v8_C0_s1` 하나를 80ep·patience 20 로 돌려 `results.csv` 를 읽음:
- patience 로 **75ep 에서 자동 정지** (상한 80 은 안 쓰임).
- **best epoch 55** (val mAP50-95 = 0.954) · **수렴점 52** (best 의 99% 첫 도달).
- **val 곡선이 평평** — ep30~65 가 전부 0.92~0.95(best 와 차이 ~0.01). **ep40 넘으면 모델이
  사실상 같음** → 멘토 지적이 실측과 일치.

    ep22 0.890 · ep30 0.917 · ep43 0.943 · ep55 0.954(best) · ep65 0.948 · ep75 0.935

**결정: `EPOCHS = 60`, `patience = 20`.** 근거:
- `best.pt` 는 **정점(~55) 가중치**로 저장된다 — 천장은 "정점을 담고 확인할 만큼"이면 되고
  그 위는 낭비. **60 = 정점(55) + 여유 5.**
- 곡선이 평평하므로 60·70·80 의 결과 모델은 사실상 같다 → **낮게 잡아 낭비만 버린다.**
- **55 미만은 수렴점(52) 전이라 언더트레이닝** → 하한. 그래서 "무작정 낮게"가 아니라
  정점은 담되 그 위 군더더기를 버리는 60.
- **C0·C3 동일 적용** → A/B 유효. 절대 수치는 epoch 에 움직여도 **델타는 견고**.

**정직한 경계.** 이 수렴점은 **합성 val 기준**이지 realfire 전이 정점이 아니다(realfire 로
epoch 를 튜닝하면 held-out 이 오염되므로 안 함). "합성 과제를 배울 만큼만, 임의의 과잉 없이"로
읽는다. 프로브 모델은 측정용이라 버린다(`runs_phaseB` 불변).

## 6. 지표와 보고 (의사반복 방지)

- **주 지표**: realfire `real_flame_rate` — **영상 단위로** 보고(영상 N개 = 독립 N개,
  프레임은 상관 → 의사반복 금지). "N개 중 몇 개에서 검출 ≥ 기준" + 풀링값엔 군집 CI 주석.
- **부 지표**: `real_fp_rate` — 현실성이 오탐을 **줄이나 늘리나**(v1 modelA는 늘렸음 — 경계).
- **가드(회귀 확인)**: synth clean 검출 · **노이즈 강건성 곡선** · **ablation(지름길 여부)** 이
  v1 대비 안 무너지는지.

## 7. 성공 기준 (실행 전 확정)

**돌리기 전에 못박고, 실패해도 그 수치를 그대로 보고한다.**
- **성공** = C3의 realfire가 C0보다 **영상 단위로 유의하게↑**(CI 비겹침), **동시에
  real_fp 악화 없음**, **가드 지표 유지**(강건성·ablation).
- **부분 성공** = C3 > C0 이나 여전히 낮음(예 0.31→0.45). **실패 아님** — 이전 저장소가
  좋은 도구로도 못 닫았다는 사전지식상 예상되는 결과. "간극 잔존"을 명시.
- **음성(가설 기각)** = C3 ≈ C0. **병목은 불꽃이 아니었다** → 배경·씬·패러다임·temporal로
  방향 전환. 값진 음성 결과.

## 8. 단계별 진행 (비용 방어)

- **Phase 0 — 값싼 육안 검증(재학습 없음)**: 아틀라스 몇 장을 급식실 배경에 C3 방식으로
  합성 → **v1 컷아웃과 나란히 눈으로 비교**. 발광·통합이 실제로 좋아졌는지 먼저 확인.
  *별로면 합성 파이프라인부터 손봄.*
- **Phase 1 — 핵심 A/B**: C0 vs C3, **baseline만, 5 seed**, 동일 realfire → **핵심 수치 하나**.
  - C3 ≫ C0 → 가설 확인, Phase 2로.
  - C3 ≈ C0 → 병목은 불꽃 아님 → 방향 전환(며칠 아꼈음).
- **Phase 2 — 확장(Phase 1 양성일 때만)**: 성분 분해(C1·C2), v11 미러, **realfire 확장**
  (안 쓴 오일화재 더 추가 → 군집 n↑), 노이즈 강건성 재확인.

## 9. 결과 해석 트리

- **C3 ≫ C0** → 컷아웃이 병목이었음(진단 확인).
- **C3 > C0 이나 여전히 낮음** → 현실성은 도우나 **2D 합성의 천장·temporal** 잔존
  (이전 저장소 부분성공과 정합).
- **C3 ≈ C0** → 불꽃 아닌 딴 축이 병목.
